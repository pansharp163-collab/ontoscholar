## 项目一句话

七个职责单一的 AI Agent 在本体约束下协作,把科研文献转化为以"研究主张"为核心、每条可追溯至原文证据的知识图谱;**在判定矛盾之前,先依据实验条件判定两条结论是否可比**。研究者从"逐篇阅读者"转变为"知识策展人"。

## 架构与 SciencePal 的关系

- **SciencePal 研发工作流**：用于文献检索与初筛。
- **应用中的 SciencePal 接口**：通过服务端 TypeScript 调用 REST API，支持 SciencePal 对话、研究问题关键词提炼、知识库覆盖核查及证据返回。研究问题详情页的“知识库关键词检查”调用 `checkKnowledgeKeywords`；“SciencePal 对话”页面调用 `sciencepalChat`。
- **应用中的文献检索与筛选**：研究问题详情页的“检索与筛选”按钮调用 `discoverPapers`，使用 Base44 联网模型 `gemini_3_flash`，每次最多返回6篇文献并保存筛选结果。
- **主张抽取与可比性分析**：由自研应用组织数据、提示及审核流程。研究主张抽取使用 `gemini_3_flash`；可比性分析由模型依据条件比较要求辅助判断，结果需由研究者核验。R1–R9 为方法设计中的规则框架，当前代码未实现独立的确定性规则引擎。
- **本体与人工审校**：以结构化研究主张组织方法、指标、条件与证据，支持概念对齐、概念提议和人工审核。Brick / Project Haystack / Xeto 用作领域建模及类型规格设计参考，不表示已部署其完整运行时或验证引擎。

## 资源使用补充说明（2026年10月30日）

本说明补充已提交的《资源使用声明》。SciencePal 通过 REST API 支持 Agent 对话，以及研究问题关键词提炼、知识库覆盖核查和证据返回；其底层模型由 SciencePal 平台管理，本项目未固定具体型号。Base44 除承担应用托管、身份认证与数据存储外，还提供模型调用服务：当前提交代码中的文献检索与筛选、研究主张抽取使用 Base44 接口中的模型标识 `gemini_3_flash`，可比性分析与知识查询通过 Base44 模型接口调用，代码未显式指定型号，实际模型由 Base44 平台配置决定。相关服务按平台账户权限及适用条款使用，密钥仅在服务端配置，不随作品公开。

## 仓库内容

- `src/`：前端界面与业务交互代码（Base44 构建）。
- `base44/functions/`：文献检索、主张抽取、可比性分析、知识查询、SciencePal 对话及关键词核查等服务端函数。
- `base44/shared/sciencepal.ts`：SciencePal REST API 调用及运行结果处理。
- 本体设计、评估说明、使用方案、知识库、人工裁定日志和演示视频等材料见上述 Drive 材料包对应目录。

## 评估与诚实声明

- 研发记录包含文献检索、筛选理由和人工核验案例；引用真实性抽查仅适用于对应抽查批次，不等同于全文证据支持率或整体系统准确率。
- 源码已包含 SciencePal REST API 调用；实际运行依赖服务端授权、Agent 配置及平台可用性，源码接入不等同于所有运行场景均已验证通过。
- 后续验证：证据支持率全文抽检、独立测试集盲测、首个完整本体演化闭环。
- 关键词未命中仅表示当前可检索知识库未返回匹配证据，不能直接认定整个研究领域存在研究空白；可比性与矛盾分析结果均需研究者结合原文核验。
- 文献版权及许可按原始来源逐篇适用；领域标准与第三方代码不作为本人原创成果声明。
